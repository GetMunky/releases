# MUNKY release repository — maintainer rules

Mission: revolutionize how everyday people experience the internet through one
free consumer environment for understanding, exploration, creation, collaboration,
authorized action, and continuity. This repository distributes releases; it is not
a separate product roadmap or a paid-browser storefront.

Keep this repository public-binary oriented. Do not copy private application source,
internal audits or plans, account data, credentials, signing material, or customer
traces here. Maintainers use the single canonical experience plan in the private
engineering repositories; public availability is established by actual release evidence.

Never overwrite a published version's bytes or invent checksums, sizes, signing,
notarization, platform compatibility, or autonomous-task acceptance. Preserve existing
release tags, attachments, metadata, and updater contracts. Source updates do not
update installed applications. Publishing binaries or changing feeds requires a
separate authorized and validated release operation.

Do not claim a formal OpenAI partnership, special AGI access, universal functionality,
or achieved 10x performance without evidence. Keep public copy broad and truthful,
not profession/busywork focused. Documentation changes do not authorize customer
tasks, payments, security-policy changes, or release publication.
